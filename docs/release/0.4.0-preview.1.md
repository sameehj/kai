# Kai 0.4.0-preview.1 (pre-release)

One Kai window that shows what Kai recorded, and Ask Kai, which answers from those records only. Identify a build by its commit: `kai version` prints it.

## What changed

- **The Kai window** (docs/design/kai_v11.html):
  - a sidebar with Activity, Agents, Decisions and Ask Kai, with Settings at the bottom;
  - the workspace in the toolbar, picked automatically from the most recently active session;
  - one header that names the most important problem ("Cursor isn't connected", "Kai's settings can be changed by other programs", "Kai is off"). One agent that isn't connected never reads as all checks off.
  - The old Agent Control page and the "What each agent can reach" list are gone.
- **Activity:** one grouped list of what Kai recorded today in the workspace, with filters (All, Files, Connections, Stops) and search.
  - Each row opens its evidence: Outcome, Agent, Evidence source, Session, Scope and up to four examples.
  - Tool calls Kai saw through a hook are labelled **Requested**: the hook runs before the tool, so Kai doesn't confirm the result.
  - Connections are listed only when Internet watching is on.
- **Agents:** one row per agent on this Mac.
  - The states are "Connected · N working", "Not connected · running · activity unknown" and "Not connected · activity unavailable". Connected is about Kai's integration only. *Working* means a connected agent ran a command in the last 15 minutes.
  - Each row states what that agent reports, and opens Activity filtered to that agent.
- **Decisions:** recorded stops, one entry per stop. Each opens a sheet with the reason, what a retry would get now (`kai why`), technical details and **Ask about this**.
  - For an eligible file read (such as `.env.local`), **Allow for this session…** asks you to confirm, then lets that one agent read that one file with its file tool for 5 minutes.
  - Private keys and Kai's own settings can't be allowed from the app. The sheet says "Run it in your own terminal".
- **Ask Kai** (⌘K to ask, ⌘J to hide the chat):
  - Answers are built deterministically from Kai's records (`kai activity`, decisions and `kai why`, `kai snapshot`, `kai status`), each with a "Based on: …" line.
  - Kai answers questions about: what happened today, which files were read or changed, what Kai stopped and why, whether an agent is connected, which destinations were contacted, and what Kai can't see.
  - Anything else gets "No matching record" and the list of what Kai can answer.
  - A model can only reword the answer. It receives the answer and the question, with paths, commands and URLs marked as untrusted data, and it can't add buttons: buttons come from the records.
  - A rewording that drops any number is discarded.
  - Chats stay on this Mac, per workspace, for 30 days.
  - Models (Settings → General → Ask Kai):
    - Apple Intelligence where available;
    - a local model through llama.cpp, downloaded only after you agree, and checked against a pinned SHA-256;
    - templates, which are always there.
- **Opt-in activity recording** (`record_activity on`, off by default; Settings → General): one metadata line per agent tool request in `~/.kai/activity.jsonl`.
  - It records the agent, session, workspace, tool, operation, the file path for file tools, the first word of a shell command, the MCP server, and Kai's decision.
  - It never records file contents, arguments or full commands. Files rotate daily and are deleted after 7 days.
  - New command: `kai activity --json [--since 24h] [--workspace PATH]`.
- **Fewer false stops in MCP calls:** a value that names where a secret lives is no longer taken for the secret. That covers `os.environ[…]`, `process.env.X`, `ENV[…]`, `getenv(…)`, `${X}`, `{{x}}`, `$X` and file paths such as `certs/server.pem`. A real-shaped token is still stopped.
- **Shorter stops:** what the agent reads is one sentence (what was stopped, and why), then "Ask the user if this is needed." The terminal `kai allow-file … --for 1h` instruction is no longer in agent-facing text. The command still exists.
- **Popover:**
  - "Kai · N working sessions", the health line, agent rows, the latest stop, Ask Kai…, Pause… and Settings;
  - the duplicate stop card is gone;
  - the double period ("Kai..") is fixed.
- **Brand:** the purple-and-teal shield logo and app icon. Teal is for actions and selection, purple for the brand only. Neutral greys follow light and dark mode. Amber means needs attention, and red means Kai is off. The menu-bar icon is a plain template shield.

## Limitations

- **Hook-level checks only.** Kai checks what the agents report through their hooks. Scripts, subprocesses and editor extensions aren't checked, and Activity can't list what they touch.
- **Internet is Watch-only.** When it's on, Kai lists destinations and blocks nothing. A connection doesn't show what was sent.
- **Files protection isn't in this release.**
- **Activity recording is opt-in.** With it off, Activity and Ask Kai have only Kai's stops.
  - Claude Code reports reads, edits and writes.
  - Cursor reports reads only, not its editor's writes.
  - Codex reports commands and MCP calls, with no file events.
- **Ask Kai answers only from Kai's records.** "No matching record" never means it didn't happen.
- **"Allow for this session"** is one agent, one exact file, reads with the file tool only, for 5 minutes. Kai's grants are per agent, not tied to one session ID, so another session of the same agent could use it within those 5 minutes.
- **Apple Intelligence** needs macOS 26 with Apple Intelligence on, and a Kai built with the macOS 26 SDK. This package was built with Xcode 15.2 (macOS 14 SDK), so Apple Intelligence shows as not available, and Ask Kai uses the local model or templates.
- **Manual QA:** none for this preview, by the owner's decision. The automatic checks below passed.

## Ask Kai's local model

- **llama.cpp:** release `b12182`, the xcframework pinned in `app/macos/Packages/LlamaBinary` (SwiftPM checksum `5c9e766aa026046c04d80d27f187cb76317be00089daebb94aa52768f090bd8b`). llama.framework is weak-linked, needs macOS 13.3 or later, and runs on the CPU on Intel Macs.
- **Default model:** Qwen3.5-0.8B Q4_K_M (Apache-2.0) from `unsloth/Qwen3.5-0.8B-GGUF` at revision `6ab46149…`.
  - Size: 532,517,120 bytes.
  - SHA-256: `bd258782e35f7f458f8aced1adc053e6e92e89bc735ba3be89d38a06121dc517`.
  - No official Qwen GGUF repository exists.
- **Optional:** Qwen3.5-2B Q4_K_M (`unsloth/Qwen3.5-2B-GGUF` at `f6d5376b…`, 1,280,835,840 bytes, SHA-256 `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`). It wasn't tested for this release.
- **Not in the package:** the model is downloaded on first use only, after a consent sheet, to `~/Library/Application Support/Kai/models/`.
- **Small models can drop facts.** Kai keeps a model's rewording only if every number survives and it stays short; otherwise it shows the template answer.
- **Team-signed builds only.** The local model works in Developer ID builds. Ad-hoc builds (`make app`, CI) show it as not available.
