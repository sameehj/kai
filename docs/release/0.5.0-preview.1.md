# Kai 0.5.0-preview.1 (pre-release)

The launch build. Identify a build by its commit: `kai version` prints it.

## What changed

- **Now (the new home).**
  - One card per live agent session: the agent's logo, project, terminal tab and topic (as the agent reported it), Working or Idle *n* min, when it started, and counts of reads, edits, commands and stops.
  - Directly under the agent line, what it did last: "Editing Pricing.tsx · now", "Read package.json · 2 min ago". With recording off it says "Recording is off: Kai keeps only stops" with **Turn on**.
  - A stop turns the card's top edge amber and shows one line ("Kai stopped a read of .env"), which opens the decision.
  - Nested sessions and background services sit under their parent. Sessions that ended today fold into "Earlier today".
  - Connected agents with no session get a slim row ("Codex · connected · not running today"), with the `/hooks` step only while Codex's trust is pending.
  - Kai counts only what the agent reports: Cursor cards say "edits: not reported by Cursor", Codex cards "files: not reported by Codex".
  - The header count ("2 working · 1 idle"), the toolbar pill and the popover come from one source.
- **Activity, one timeline.**
  - Kind filters: All · Files · Commands · Connections · Stops. Project, agent and session menus; "Clear session ×".
  - Grouped by session ("Claude Code · acme-web · 18:42–now"). Each event opens a sheet with what happened, the evidence, the outcome and the session, plus **Ask about this →**. Stops open the decision.
  - Empty states say why: a filter hiding a working session ("Claude Code is working in acme-web, not in api-server", **Show all projects**), recording that started after a session began, recording off, or no activity today.
- **Navigation.** Now, Activity and Ask Kai, with Settings at the bottom.
  - Decisions is now Activity → Stops.
  - Agents is now Settings → Agents. Checks and exceptions are now Settings → Rules.
  - The project picker is gone from the toolbar: every project is in scope.
  - `kai://settings/<page>` links keep working. `kai://settings/decisions`, `kai://decisions` and `kai://agents` redirect.
  - Toolbar dot: teal when fine, amber when something needs you, red when Kai is off, grey only when no agent is connected.
- **Real agent logos.**
  - Kai uses the icon of the installed Cursor, Claude or Codex/ChatGPT app.
  - Otherwise it uses the vendors' official marks: Anthropic's press kit, cursor.com/brand and openai.com/brand. See [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md).
  - No initials tiles.
- **Ask Kai: the model in the chat.**
  - A model chip sits next to Ask and in the Ask header: "Templates ▾", "Qwen 0.8B ▾" or "Apple Intelligence ▾". Its menu gives each option's description, size and status, with Download, Use and Delete.
  - The consent line is next to Download: "Downloads ≈500 MB from Hugging Face (pinned version, checked with SHA-256). Nothing you ask is sent anywhere."
  - Progress shows on the chip ("Qwen 34%"). Once the download is verified, Kai switches to the model and says so in the chat.
  - A one-time card in the chat offers the download, with the same consent line.
  - Settings → Ask Kai shows the same control.
- **Model safety.**
  - Coverage limits and "Based on" are Kai's own footer under every answer. The model gets only the main answer, so rewording can't drop "Cursor doesn't report edits."
  - Release builds load only hash-verified catalog models: `$KAI_LLAMA_MODEL` and arbitrary model files are debug-only.
- **Popover:** up to 3 sessions, the latest stop, **Open Kai** and an Ask field.
- **First launch:** three panes (agents connected, the Internet watching step, Ask Kai with the model chip). Each pane has **Skip**, and the welcome is shown once.
- **Engine.**
  - `kai activity --json` adds `sessions`: counts and the newest 40 events per Kai session, with paths and a command's first word only. It also adds `first_record`.
  - Each activity line carries Kai's session key (`ks`), and `kai snapshot --json` lists `activity_keys` per session, so records and sessions match.
  - Kai's own health check (`kai status`) is no longer recorded as agent activity. 0.4.1 wrote it every few seconds, and those old lines are skipped when read.
- **Commands in the UI** show only the program name ("Ran npm", "Kai stopped a command"), never the command line.

## Not changed

Evidence levels (requested / tool-reported / confirmed / unknown). No model in the decision path. Storage Wall and Network Wall enforcement; Internet is Watch only. Private keys can't be allowed from the app. Recording stays on by default, metadata only, kept 7 days.

## Known limits

- Records written before 0.5 have no session key. They join a card only when one session of that agent works in that project.
- The model runs inside the Kai app process.
