# S5 — Agents window (live test)

A dedicated **Agents** window (SwiftUI), opened from the menu's "Agents" link
and the `agents` window scene. Reads the read-only CLIs from S1–S4
(`kai agents --json`, `kai sessions --json`) and the live `GrantManager`,
refreshed on a 3 s timer.

## What it shows

- **Left — Agents** (`AgentsSidebar`): each agent with hook state (installed /
  missing / failing / not installed), wall recognition, and running-session
  count. Clicking an agent filters the sessions to it. An "Unattributed
  processes" section is present (live count is a documented follow-up).
- **Main — Sessions** (`SessionRowView`): agent, topic (labelled "reported by
  agent", shown as "(no topic reported)" when absent), project, and ended state.
  **Sorted needs-attention first**, then active before ended, then newest first.
  Filters: Running / Ended / All. Pending decision cards (and pending policy
  changes) appear at the top via `ApprovalsSection`.
- **Detail — Session** (`SessionDetail`): agent, topic (labelled reported-by-
  agent), project, host app, state, session id, and the **permissions** for that
  session (`grants.grants` filtered by `session_id`) with Revoke.

The view-model logic lives in `AgentsModel.visibleSessions` (filter + sort) and
the `*Label` computed properties, as pure functions.

## Tests

No C changes; `make test` stays green (exit 0) from S4. The window is SwiftUI
and the repo has no Swift test target, so the view-model logic (needs-attention
sorting, filters, the reported-by-agent labelling, "(no topic reported)") is
factored into pure functions and verified by review + the live/visual test
below. The underlying data (`kai sessions`/`kai agents --json`) is covered by
S1/S2 automated tests.

## Deferred within S5 (documented)

- **Unattributed-processes live count.** Needs the ES wall to report agent-tree
  processes it put in no session (e.g. launchd-detached). The section is present
  as a placeholder; the count is the next increment.
- **Activity pane + observed summary (counts, top lists)** in the detail: needs
  the denial records to carry the ES session id (see S3's deferred note). Shown
  as permissions-only for now.
- **Grant lifecycle labels** ("Not yet active" until the wall observes the grant,
  then "used") belong to the decision-card lifecycle in **S6**.
