# Kai 0.4.1-preview.1 (pre-release)

Six fixes from using 0.4. Identify a build by its commit: `kai version` prints it.

## What changed

- **Kai connects your agents.** On first launch, after every app update, and whenever a new agent shows up, Kai runs its setup (`kai install <agent>`) for every agent it detects, as you, from the app. Each agent has one switch in Settings → Advanced → Agents, **On** by default. Turning one off is remembered, and Kai won't reconnect it on its own; so is `kai uninstall <agent>` run while Kai is open. After connecting, Kai says once: "Kai connected Claude Code, Cursor and Codex" (only the agents it found).
- **Codex needs one step.** Codex runs hooks only after you trust them. Until Kai sees Codex call its hook, one amber row says "Codex: open Codex and run /hooks once to trust Kai", with **Copy "/hooks"** and **Done** (checks again). Kai never says Codex is checked before that. `kai status --json` now reports `last_hook` per agent.
- **The popover's agent list** shows "Looking for agents…" for at most 5 seconds after launch, then your agents (from `kai status` if the session list is slow) or "No agents found" with a link to Settings → Agents. If neither source can be read, it says so rather than "none found".
- **Activity recording is on by default** for new installs and for policies that never set it. An explicit `record_activity off` stays off. It is metadata only, on this Mac only: never file contents, arguments or full commands, kept 7 days. The switch is now "Keep a list of what agents read, edit and run" (Settings → General). Kai says once that it's on; a marker under `~/.kai` keeps that from repeating.
- **Ask Kai's "Turn on activity recording"** re-reads the setting after the change. Success adds "Activity recording is on. From now on Kai keeps a list of reads, edits and commands. Earlier activity wasn't recorded." to the chat; a failure says "Kai couldn't turn on recording: <reason>". Buttons on older answers disappear once what they offered is already true.
- **Internet watching, step by step** (Settings → Internet, and a popover row when it isn't on). Before macOS asks, Kai says where: System Settings (macOS 15 and later: General → Login Items & Extensions → Network Extensions; earlier: Privacy & Security, "System software from Kai was blocked"), with **Open System Settings**, then the "filter network content" alert (click Allow). The step checks every 2 seconds and turns to "Internet watching is on (Watch only)" by itself; failures are in plain words with **Try again**. Managed Macs: [docs/internet-mdm.md](../internet-mdm.md). Enforcement is unchanged: Internet stays Watch only.
- **Ask Kai answers more.**
  - New questions: is Kai on, is it recording, is Internet watching on, what can Kai see for an agent, where is a setting (answered with a link; chat never changes a setting), which version, what can you answer.
  - Answers come from real state: policy switches, `kai status`, the walls and each agent's evidence level. "What happened today" now shows sessions per agent, what was recorded, stops, and the recording and Internet state, in at most 4 lines.
  - Questions are normalised (case, punctuation, a leading `=`, `/` or `?`) and one-letter typos in longer words are tolerated. 62 phrasings are tested.
  - Unmatched questions get "I can't answer that from Kai's records yet" and three suggested questions.
  - The Ask page shows where answers come from ("Templates", "Local model · Qwen3.5 0.8B", "Apple Intelligence"), with a one-time card to download the local model after the same consent sheet. A downloaded model is used automatically; the template answer shows at once and the rewording replaces it when ready ("Loading model…" the first time).
  - With a model, a question Kai's own matching can't place is sent to the model **as the question text only**, which must answer with one label from a fixed list; anything else is ignored. The answer is still built from Kai's records.
- **Fewer false stops on file reads.** A read is stopped for what a file holds only for a known token format, a private key or one of your own rules. A generic key=value guess (`password = "…"`, `secrets.GITHUB_TOKEN` in a workflow) no longer stops it. MCP argument checks are unchanged.

## Not changed

Storage Wall and Network Wall enforcement; Internet is Watch only. No model in the decision path. Private keys can't be allowed from the app. Touch ID still guards loosening.

## Known limits

- A real password written as a plain `password = "…"` line in a file is no longer stopped on read (the generic guess above). Known formats (GitHub, AWS, Slack, private keys, …) still are.
- The System Settings deep links differ between macOS versions; Kai opens the closest pane it can.
- There is no separate onboarding screen; the "Kai connected …" note appears in the popover, the Agents page and Settings.
