# Kai 0.5.1-preview.1 (pre-release)

The public preview. Identify a build by its commit: `kai version` prints it.

## What changed

- **Internet: Watch, then block what you choose.**
  - Settings → Internet has one control: **Off · Watch · Watch + block my list**. The subtitle and the status badge follow the state (teal when watching is fine, amber only when macOS needs you).
  - **Blocked sites** is one list: a host there is the same rule as `kai block <host>`. The hooks keep stopping shell commands and web fetches that name it, always. In **Watch + block my list** the network extension also refuses new connections from agent processes to a listed site (and its subdomains), or to a listed address or range (`egress_block` lines in the policy). It drops them at once, with no card, and records `block … blocked site <host>`.
  - Under the list, verbatim: "Kai refuses agents' direct connections to these sites. An agent could still reach them another way, for example through a proxy or a site that isn't on your list."
  - A starter set (paste and file-sharing sites, agents' telemetry hosts) is offered once, every box unchecked.
  - **Block site** on every connection row in Activity and every connection answer in Ask. In Watch, Kai asks once: "Turn on blocking for your list?" A refused connection shows as **Stopped**, with **Unblock**, in Activity and on the session's Now card.
  - The allowed-destinations list moved to Settings → Advanced → Internet as **Never block these**. It never overrides a block entry for the same host.
  - In Watch + block my list with a non-empty list, agents' QUIC (HTTP/3) is turned off so Kai can read the site name; they fall back to HTTPS.
  - Telemetry rows say what is true: "Kai turned on Claude Code's own telemetry opt-out", or "Blocked by Kai (your list)" when the telemetry hosts are on the block list.
  - Strict "only allowed hosts" stays compiled out of release builds.
- **Kai is the subject of every stop:** "Kai stopped Claude Code's command", "Kai stopped Claude Code reading .env", "Kai stopped Cursor's connection to paste.example.org", in the popover, Now, Activity, Ask and notifications.
- **Card counts match Activity.** A Now card counts the whole session; when recording started later it adds a muted line ("Recorded in Activity since 16:17: 4 file actions, 12 commands."). Activity's group headers show the same numbers. **Open →** always lands on the All filter.
- **Popover numbers.** "Today: 312 actions · 5 stops · 14 connections" (stops amber above 0; connections only while Internet is on). Each session row: "Ran a command · 6 min ago · 261 commands · 5 stops". The latest stop: "Kai stopped Claude Code's command · 1h".
- **Health line.** "Connected · hooks OK" at rest; "Checking hooks…" only while a check runs; "Claude Code's hooks need repair" in amber with **Repair**.
- **Activity rows.** Paths relative to the session's project; outside it "outside project" and the file name (the full path only in the detail sheet); temporary and scratch files grouped ("tmp · 3 files"). Plain labels: Agent asked to read / write / run, Seen, Stopped; each keeps its evidence level in the sheet.
- **Session cards.** Zero counts are hidden; "Just started" replaces "No command recorded yet"; nested sessions and background services sit under their parent with a short explanation.
- **Ask about this** opens a new chat titled after the item, starting with it quoted. It never goes into the current chat.
- **Codex icon fixed.** The bundled OpenAI mark has light and dark variants; drawn as a plain image, the black mark landed on the dark tile and showed a blank grey square. Bundled marks are now drawn for the current appearance.
- **The stop's decision sheet** names what was stopped with Kai as the subject and adds **Not right**.
- **README pictures** come from `make screenshots`: the real views and a fixture data set, light and dark.

## Engine

- New egress mode `blocklist` (`egress blocklist`), effective in release builds; `egress_block <host|ip|cidr>[:port]` lines share the `egress_allow` parser. The block list wins over `egress_allow`. Only agent-attributed flows are affected.
- `kai status --json` adds `internet: {mode, enforcing, blocked_sites}`; `kai status` says "Watch + block my list: refuses agents' direct connections to N listed sites; records the rest".
- `kai activity --json` adds `today` (records since local midnight), for the popover.
- Tests: block list parsing, subdomains, IP and CIDR, block wins over allow, non-agent flows unaffected, a release-build test (`blocklist` effective, strict `block` clamped to `log`), and app tests for the words, counts, paths and logos.

## Not changed

Evidence levels (requested / tool-reported / confirmed / unknown). No model in the decision path. Storage Wall enforcement. Private keys can't be allowed from the app. Recording stays on by default, metadata only, kept 7 days.

## Known limits

- Watch + block my list is not a firewall: a proxy, another site, a script that resolves a host by itself or any route the extension doesn't see as the agent's can still reach a blocked site.
- Blocked sites added as plain hosts live in `agent-rules.json`, which a program with your permissions can edit (as for `kai block`).
- The model runs inside the Kai app process.
