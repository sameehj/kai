# Kai Preview v0.2.0-preview.1 (release candidate)

**Give AI more work, not more access.**

> **Kai Preview checks supported actions inside Claude Code, Codex and Cursor before they run.** It is an extra safety layer, not isolation or OS-level enforcement: hooks run with your permissions, cover only the actions each agent reports to them, and a program the agent runs can get around them. Codex runs hooks only after you trust them.

Kai Preview checks inside your agents. OS-level protection for files and internet comes with the Kai app in an upcoming release.

**Requirements: macOS 13 or later; Linux and Windows aren't supported.**

## How it works, in three steps

1. **Install Kai.** Open the package. It installs `kai`, refreshes Kai's hooks in the agents that already have them, and removes an earlier Kai's Chrome helper. Run `kai install` for any other agent.
2. **Kai checks your agents and stops unwanted moves before they run**: reading your keys, sending files out, and secrets in the prompts you submit. Each stop says what happened, why it matters, and what you can do.
3. **You decide what they can do, narrowly.** When Kai stops something legitimate, its message gives the exact command to run in your own terminal, for one agent, one operation, one target, with an expiry:
   `kai allow-file`, `kai allow-fetch`, `kai allow-mcp`, `kai allow-upload`, `kai block`, `kai rules`, `kai undo`.

Then: `kai demo` shows the checks working with a fake secret. `kai demo --live` confirms it with a real agent session, which uses its model quota. `kai status` shows what's checked for each agent.

## What's checked

Per agent and action, with evidence: [docs/COVERAGE.md](../COVERAGE.md). In short:
- **Claude Code:** file-tool reads and writes, shell commands, your submitted prompts, MCP tools, web fetches.
- **Codex:** shell commands, your submitted prompts, MCP tools (after you trust Kai's hooks in Codex).
- **Cursor:** file reads, shell commands, your submitted prompts, and MCP tool arguments (secrets only).

**Not checked:** what a program the agent runs does on its own, detached or background processes, tool results, the agent's other model traffic.

## What's new since 0.1.0

- Fixed messages for every stop: what, why, and the narrow command where Kai identified the target.
- Narrow grants with expiry (`kai allow-file`, `allow-fetch`, `allow-mcp`, `allow-upload`). Files are pinned to the exact file, so a replaced or re-linked target no longer matches.
- `kai status` per agent: Installed, Configured, Trusted, Self-test, Live verification. `kai demo` and `kai demo --live`.
- Policy integrity: Kai notices some changes made outside Kai, never all, and prevents none. If the policy goes missing after Kai wrote it, tool checks stop every action.
- Web fetch is checked (Claude Code). MCP tools work without the Kai app.
- Installer: welcome and readme pages, and Kai's hooks refreshed where already installed (backups kept, changes logged).

## Limits

- No OS-level enforcement in this preview (no Files or Internet protection).
- Kai's rules and policy can be edited by any program with your permissions.
- `kai allow-fetch` governs only the agent's fetch tool, never other connections to that host.
- No browser coverage: the Chrome extension was removed (Security Plan v1.0); AI chat sites in a browser aren't checked.

## Verify the download

```sh
shasum -a 256 -c Kai-Preview-0.2.0-preview.1.pkg.sha256
spctl --assess --type install -vv Kai-Preview-0.2.0-preview.1.pkg   # "source=Notarized Developer ID"
```

Remove it: `kai uninstall all`, or `kai uninstall all --purge` to also remove Kai's settings and log.
