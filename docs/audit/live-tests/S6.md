# S6 — Decision cards, pause, lifecycle (live test)

Tier-aware decision cards, per-session pause, and the lifecycle wiring on top of
the S4 grant engine.

## What changed

- **Tier-aware decision card** (`ApprovalCard`, `Approvals.swift`): actions now
  depend on the resource tier carried on the pending request:
  - **never** (tier 4): "Kai protects its own settings; this can't be approved
    from here" and **no Allow button** (only Dismiss).
  - **break-glass** (tier 3): "Override with Touch ID…" → `approve` runs
    LocalAuthentication, then signs a read-only grant capped at 15 min (S4).
  - **override** (tier 2): "Override for this session…".
  - **normal/confirm**: Deny / Allow once / Allow this process.
  The trust-store/explanation note ("changes which websites this Mac trusts") is
  already shown from the pre-S1 fix.
- **Per-session pause** (`kai_session_pause[_write]`, `src/session.c`):
  time-boxed, auto-resuming skip for ONE session; never-tier (control store)
  still applies. The storage wall caches the paused-session set off the hot path
  (`writeHealth`) and, in `authorize`, allows a paused session's SOFT-protected
  ops (logged as `would-block (session paused)`) while still blocking builtin
  control paths. CLI: `kai pause session <id> [min]` / `kai resume session <id>`
  (refuse agents). App: "Pause Kai for this session (15 min)" in the session
  detail.
- **Grouping** of identical grants and recent items (counts) landed in the
  pre-S1 menu fix and the Agents window.

## Automated tests — PASS (`make test`, exit 0)

`run_storage_tests` → `test_session_pause`: not paused by default; pause for 15
min registers; auto-resumes after the window; resume clears it; a traversal
session id is refused. The never-tier card having no actions is a property of
`ApprovalCard` (tier 4 branch); break-glass Touch ID + read-only cap is the S4
engine path (`test_grant_tiers`).

## Deferred within S6 (documented)

- **Add-permission form (grant ahead of time).** It needs a *session-wide*
  grant that matches any process in the session, but the matcher still binds a
  grant to a specific pid+pidversion. Relaxing the pid check for a
  session-scoped grant (match on session id instead) is a small S4 matcher
  refinement; until then "Allow this session" covers the requesting process (and
  its forked children), not brand-new processes. Flagged for the next increment.
- **Full lifecycle status line** (granted → received by wall → used): "used" is
  already audited (`grant used`); surfacing the intermediate "received by wall /
  Not yet active" state needs the wall to report which grant generation it has
  loaded, tied back to the card. Shown as grants with countdown for now.
- **Notification grouping specifics** (rate-cap, badge fallback) build on the
  existing grouped notifications (U2).
