## Can an agent write the policy today?
- **With the storage wall active (now, v17 block):** an agent's `open()`/write of
  `~/.kai/policy` is denied by the ES wall (control path, un-exemptable) — so going
  forward it is protected at the OS level.
- **When the wall was off (e.g. at 21:58 if it was off then):** the ES wall gives
  no protection; only the agent-hook layer blocks a *hooked* command touching
  `~/.kai`. A direct file write by an agent, not routed through a hook, would have
  succeeded. So a write while the wall was off is possible and unattributable.
