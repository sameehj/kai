# S2 — Agent inventory (live test)

`kai agents` lists each recognized agent with: hook state (installed / missing /
failing / not found), wall coverage (recognized / not), active session count,
and a detail line. Engine-only (no extension change); the Agents *window* is S5.

## What it reports

Per agent (claude, cursor, codex — the hook-managed ones — plus any
user-defined agents the policy names):

- **hooks**: `installed` (present and the live check passes), `failing`
  (present but broken — reason in detail, from `kai_health_agent`), `missing`
  (agent config dir exists but no Kai hook), `not found` (no config dir),
  `n/a` (a wall-recognized agent Kai installs no hooks for, e.g. gemini).
- **walls**: `recognized` when the policy (which carries the built-in agent
  rules both walls classify by) has a rule for it — `kai_agent_wall_recognized`.
- **sessions**: active sessions for the agent, counted from the S1 registry.
- **detail**: the health problem, or "run: kai install <name>" when missing.

`kai agents --json` emits the same as an array.

## Automated tests — PASS (`make test`, exit 0)

- `run_storage_tests` → `test_agent_inventory`: the built-in agents (claude,
  cursor, codex, gemini) are wall-recognized, an unknown name is not, and a
  user-defined `agent aider …` rule makes aider recognized.
- Hook-state detection (installed / missing / failing / "older Kai") is the
  existing `kai_health_agent` logic, already covered by the cli tests
  (`status: installed`, `missing kai program is a problem`, `unguarded hooks are
  flagged`).
- Sandbox smoke (fixtures): claude with guarded hooks pointing at a missing
  binary → `failing`; cursor dir without hooks → `missing`; no codex dir →
  `not found`; gemini → `n/a` recognized; an active session is counted.
